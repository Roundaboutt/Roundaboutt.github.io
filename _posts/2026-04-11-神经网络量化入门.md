# 什么是量化？

我们都知道，大模型虽然强大，但它们的参数量往往大得惊人，这让显存不堪重负。量化（Quantization）就是给模型“瘦身”的关键技术。在未量化的模型中，我们通常使用FP16（16位浮点数）来存储权重。想象一下，如果把所有权重画在数轴上，FP16就像一把刻度非常密集的尺子，能极其精准地衡量每一个参数的大小。但是，这种精度往往是过剩的，而且非常占地方。量化的核心目的，就是把这把“密尺子”换成一把“疏尺子”，用更少的比特位（比如8位或4位）来表示这些数。

我们要探讨的核心，其实就是如何建立一个从实数域 $R$（FP32/BF16）到整数域 $Z$（INT8/INT4）的映射函数。



那么，一个量化后的算子是什么样的？我们以Conv为例：

从图中可以看到，input weight bias 三个参数在输入后都要先经过量化。其中 input weight 从FP32量化为int8，而 bias 从FP32量化为int32（原因我们后面再解释）。

输入参数量化完之后，还不能立刻开始计算！input 和 weight 还要转换成int32精度，这里非常重要。为什么呢？因为int8数据的计算中间结果很可能超过int8的表示范围，所以需要int32来暂存中间结果。那int8转换为int32是不是又要经过一次量化呢？不需要！只需要在高位补0就可以了。这也就解释了为什么bias一开始就量化成了int32。

那输出结果为什么还要经过一次量化呢？int8转int32不需要量化，而int32转int8可不能直接把高位截断！所以必须还需要一次量化。

# 量化的分类

## 线性量化：一把刻度均匀的尺子

**线性量化**是目前工业界最主流的方案。它的核心假设非常简单粗暴：我们认为数据在最大值和最小值之间是均匀分布的，或者说，我们强行用等间距的网格去套住这些数据。在数学上，这就是一种**仿射变换（Affine Mapping）**。

在线性量化框架下，任意一个浮点值 $x$ 都可以通过以下公式映射到整数空间 $x_q$：

$$x_q = \text{clip}(\text{round}(\frac{x}{S} + Z), Q_{min}, Q_{max})$$

其中 $S$ 是缩放因子，用于调整数值的间距；$Z$ 是零点（Zero-point），用于确保浮点数中的 0 在整数空间中能被精确表示 。

$round$是取整函数；$clip$的作用则是把最终范围框定在$[Q_{min},Q_{max}]$之内。

反量化（Dequantization）则是这一过程的逆变换：

$$\hat{x} = S \times (x_q - Z)$$

---

### 对称量化

通常用于**权重**的量化，因为权重通常分布在0的两侧（如$[−0.5,0.5]$）。

我们强制让浮点数的 $0$ 对应整数的 $0$，也就是强制 $Z=0$。 为了保持对称，我们需要选取浮点数绝对值的最大值作为边界。设 $\alpha = \max(|r_{min}|, |r_{max}|)$，则浮点范围被强制设定为 $[-\alpha, \alpha]$。 对应的整数范围通常选取有符号整数，如INT8的 $[-127, 127]$（注意这里通常舍弃 -128 以保持完全对称）。

此时的缩放因子 $S$ 变得极其简洁： $$S = \frac{\alpha}{127}$$ 

量化公式简化为： $$q = \text{clip}(\text{round}(\frac{r}{S}), -127, 127)$$ 

反量化公式简化为： $$r = S \times q$$



量化：

```cpp
float value = 1.0; float scale = 0.1;
int qt32 = round_fn(value / scale);
chat qt8 = clip(qt32, Q_MIN, Q_MAX);
```

反量化：

```cpp
float value = 1; float scale = 0.1;
float deq = value * scale;
```

---

### 非对称量化

当线性量化公式中的$Z$不为$0$时，就称为**非对称量化**。这是线性量化最完整的形态，通常用于激活值（Activation）的量化，因为激活值（如ReLU的输出）通常是非负的（$[0, +\infty)$），分布极度不对称。

当数据的分布不均匀（例如全为正数的 ReLU 激活值）时，非对称量化通过映射浮点数的实际最小值和最大值来更充分地利用 INT8 的 256 个表示位 。

**缩放因子S的计算**：

$$S = \frac{x_{max} - x_{min}}{Q_{max} - Q_{min}}$$

​    对于标准的无符号 INT8（范围为$[0,255]$），公式为：

$$S = \frac{x_{max} - x_{min}}{255}$$

其中，$x_{max}$ 和 $x_{min}$ 分别是原始浮点张量中的最大值和最小值 。

补充：为什么**激活值**的量化一般都是非对称量化？

比如ReLU，输出的值域是$[0, +\infty]$。如果使用对称量化的话，那么从 $[-\alpha, 0)$ 这个左半部分的量化区间将永远没有任何数据落入。

对于 INT8 量化来说，我们一共有 256 个刻度（$-128$ 到 $127$）。如果你用对称量化去套 ReLU 的输出，你只能用到 $0$ 到 $127$ 这 128 个刻度，而另一半（$-128$ 到 $-1$）的刻度完全被浪费了。这本质上意味着你把 8-bit 的量化强行降级成了 7-bit 的量化。**非对称量化**通过引入 **Zero Point ($Z$)**，可以将整数 0 映射到激活值的最小值 0，从而让 256 个刻度全部均匀地铺在 $[0, r_{max}]$ 之间。



既然非对称量化这么好，为什么权重不全都用它呢？

正如我们在数学推导中看到的，非对称量化在矩阵乘法 $Y = W \times X$ 中会引入额外的项。如果 $W$ 和 $X$ 都是非对称量化的，展开后的公式会包含 $S_w S_x \sum (q_w - Z_w)(q_x - Z_x)$。这个公式拆开后会产生多个复杂的交叉乘加项，给硬件带来额外的计算延迟。



量化：

```cpp
float value = 1.0; float scale = 0.1;

int qt32 = round_fn(value / scale + offset);
unsigned char qt8 = clip(qt32, Q_MIN, Q_MAX);
```

反量化：

```cpp
float value = 1.0; float scale = 0.1;
float deq = (value - offset) * scale;
```

### Power of 2

实际上就是把除以scale这个昂贵的除法计算换成了乘法与位移：

```cpp
float value = 1.3; int shift = 4;
int qt32 = round_fn(value * (2 << shift));
char qt8 = clip(qt32, Q_MIN, Q_MAX);
```

当使用 `2 << shift` 这种方式时，实际上是在利用整数流水线来处理缩放逻辑。传统的对称或非对称量化需要维护一个浮点型的 `scale`，这意味着在量化过程中，硬件必须不断地在浮点寄存器和整数寄存器之间切换，或者在浮点运算单元（FPU）中完成计算后再转回 `int8`。

而在 Power-of-2 的架构下，如果整个链路设计得足够好，我们甚至可以实现全整数运算。对于像 FP16 或 BF16 这种精度有限的格式，通过位移实现的量化不仅规避了昂贵的除法器，还减少了指令发射的开销。

### Per-Tensor量化与PerChannel量化

**Per-tensor量化**采取的是一种极其“粗犷”的策略：它对整个张量里的所有元素，无论是一万个还是十万个，都只共用同一个 $S$。这种做法在逻辑上非常简单，因为你只需要存一个标量。但问题也显而易见，如果你的张量里出现了一个特别大的离群值（Outlier），为了包容这个极值，整个缩放因子就会被拉得很大，导致那些本来很小的数值在量化后全部变成了零，这种严重的精度损失在深度神经网络的激活值中尤为常见。

相比之下，**Per-channel 量化**（在卷积层中通常对应输出通道，在全连接层中对应每个输出神经元）则显得精细得多。它会为每一个通道独立计算一个缩放因子。这意味着，即便通道 A 里的数值波动巨大，也不会影响到通道 B 的量化质量。在模型权重（Weights）的处理上，这几乎已经是工业界的标配，因为权重的分布在不同通道之间往往存在巨大的动态范围差异。



在实际的推理引擎优化中，我们通常会采取“分而治之”的策略。对于权重矩阵，由于它们是静态的，我们有足够的预计算时间去针对每个通道进行最优化处理，所以 Per-channel 是绝对的主流。但对于输入激活值（Activation），由于它们是动态生成的，实时计算每个通道的缩放因子会产生不小的延迟。因此，很多轻量级方案仍然会倾向于对激活值使用 Per-tensor，或者采用更高级的动态平滑技术（比如 SmoothQuant）来试图调和两者的矛盾。

# 量化计算怎么写？

## 为什么量化计算能加速？

现在的深度学习任务，往往不是卡在算力上，而是卡在**访存（Memory Bound）**上。也就是数据从显存（VRAM）搬运到计算单元的速度，根本跟不上计算单元消耗数据的速度。当你把 FP32 压缩成 INT8，原本需要 4 个字节存储的数据现在只需要 1 个字节。

这带来的直接好处是内存带宽需求瞬间降低到原来的 $1/4$。在同样的带宽下，硬件每秒钟能喂给计算单元的数据量变成了原来的四倍。这对于 LLM（大语言模型）的推理尤为关键，因为在解码阶段（Decoding），我们每一轮都要读取海量的权重数据。量化让你的缓存（L1/L2 Cache）能装下更多的权重和激活值，大幅提升了缓存命中率，减少了昂贵的跨级访存开销。

现代处理器（包括 Intel 的 AVX-512 VNNI 或 ARM 的 Dot Product 指令）都针对低位宽整数计算做了专门的指令集优化。这些指令可以实现所谓的 **SIMD（单指令多数据）** 扩展，在一个时钟周期内同时完成多组低位宽数据的乘加运算（MACs）。

## 量化矩阵乘法

普通的矩阵乘法怎么写？

```cpp
void matmul(float** input_a, float** input_b, float** output, const int N,)
{
    for (int i = 0; i < N; ++i)
    {
        for (int j = 0; j < N; ++j)
        {
            output[i][j] = input_a[i][j] * input_b[i][j];
        }
    }
}
```

对于int8量化后的数据，输入都是char类型，还能直接用`output[i][j] = input_a[i][j] * input_b[i][j];`吗？

显然不行！两个int8直接相乘会有溢出风险，我们要先把它们反量化回**fp32**进行计算，再将结果量化回**int8**。

```cpp
void matmul(char** input_a, char** input_b, char** output, const int N, 
            const float scale_a, const float scale_b, const float scale_c)
{
    for (int i = 0; i < N; ++i)
    {
        for (int j = 0; j < N; ++j)
        {
            float out = (input_a[i][j] * scale_a) * (input_b[i][j] * scale_b) / scale_c;
            output[i][j] = clip_(roundn_(out));
        }
    }
}
```



对于`scale_a * scale_b / scale_c`，其实可以作为一个常数直接传入函数的参数进行计算。

## 量化向量加法

```cpp
void add(char* input_a, char* input_b, char* output, const int N,
        const float scale_a, const float scale_b, const float scale_c
)
{
    for (int i = 0; i < N; ++i)
    {
        float temp = (input_a[i] * scale_a + input_b[i] * scale_b) / scale_c;
        output[i] = clip_(roundn_(temp));
    }
}
```

这里的情况就变得复杂一些了：`output[i] = input_a[i] * scale_a / scale_c + input_b[i] * scale_b / scale_c`

这里就有了两个常数：`scale_a / scale_c`和`scale_b / scale_c`，而矩阵乘法中只有一个常数。为了简化计算，我们一般会要求**`scale_a`和`scale_b`一致！**即`output[i] = (input_a[i] + input_b[i]) * scale_i / scale_c`

## 量化激活函数

比如clip

```cpp
void clip(char* input, char* output, const int N,
            const float input_scale, const float output_scale,
            float qmin, float qmax)
{
    for (int i = 0; i < N; ++i)
    {
        output[i] = fmax(output[i] * input_scale, qmin) / output_scale;
        output[i] = fmin(output[i] * input_scale, qmax) / output_scale;
    }
}
```

同样，为了简化计算，我们要求`input_scale=output_scale=scale`

于是就变成了这样：

```cpp
void clip(char* input, char* output, const int N,
            const float scale, float qmin, float qmax)
{
    for (int i = 0; i < N; ++i)
    {
        output[i] = fmax(output[i], qmin / scale);
        output[i] = fmin(output[i], qmax / scale);
    }
}
```

## 量化非线性运算

像一些涉及非线性运算的算子，如LayerNorm, sigmoid, tanh等，如果仍然使用线性量化的，精度会崩得很厉害。

为什么呢？

线性量化的核心逻辑是假设数据在整个范围内是均匀分布的，所以它用固定的步长（Scale）去切分空间。但非线性函数（比如 Sigmoid 或 Tanh）最致命的特性在于，它的**灵敏度在不同区间是完全不同的**。

在 Sigmoid 函数的中间部分（靠近零点），函数值的变化非常剧烈，输入稍微动一点，输出就会跟着大幅跳变。这里蕴含了神经网络最关键的激活信息。如果你用统一的线性步长去量化，在这个“信息高地”，你的采样点可能稀疏得根本捕捉不到函数的梯度变化，导致严重的精度丢失。而到了函数的两端（饱和区），输出几乎是一条平线，无论输入怎么变，输出都死死地卡在 0 或 1 附近。如果你还用同样的精度去描述这些几乎不变的区域，就是在浪费你宝贵的 bit 位。这种“该精细的地方粗糙，该粗糙的地方死板”的错位，就是线性量化搞不定非线性的根本原因。



有什么解决方案呢？

### 查表

最经典也最暴力的方法就是**查表法（Look-Up Table, LUT）**。对于量化后的 INT8 输入，其取值范围只有区区 256 个。既然如此，我们为什么还要在推理的时候费劲去算复杂的指数或者浮点运算呢？

我们可以在模型部署前的预处理阶段，把这 256 个整数对应的非线性函数结果预先计算出来，并存储在一个极小的数组里。当程序运行到非线性层时，直接拿量化后的输入值作为索引，去内存里找出对应的输出结果。这种方式完全绕过了复杂的数学运算，速度快到飞起。不过它也有弱点，如果你的量化位宽变高（比如 INT16），表的大小会呈指数级增长，那时候缓存缺失（Cache Miss）带来的开销可能就比直接计算还要大了。

### 泰勒展开

如果你是在那些内存极度受限，或者对延迟要求极高的 CUDA Kernel 里工作，查表可能不是最优解。这时候，我们会求助于数学，使用**多项式逼近（Polynomial Approximation）**，比如最常用的二阶甚至三阶泰勒展开，或者是更高效的 Chebyshev 逼近。

我们会把 Sigmoid 这种平滑的曲线切成几段，在每一段内用简单的乘法和加法算式来模拟它的走势。这样做的好处是，所有的计算都转化成了硬件最擅长的 MAC（乘加）指令。在量化域下，可以结合之前提到的 Power-of-2 技巧，把多项式的系数也处理成位移友好的常数，从而在不离开整数流水线的情况下，完成对非线性函数的模拟。
